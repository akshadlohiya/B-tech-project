\begin{abstract}
GPS does not work well inside buildings, so warehouses and factories need a
different way to track people, tools and vehicles. Ultra-Wideband (UWB)
radio can measure distance to within a few centimetres, but only when
nothing blocks the path between the two radios. When a metal rack or a wall
is in the way, the measured distance comes out too long, and the position
estimate moves away from the true point. This paper describes a low-cost
UWB tracking system built from ESP32 boards and DW1000 radio chips, a
Raspberry Pi 4 that computes positions, and a 3D ``digital twin'' that shows
the tracked tags live in a web browser. The main part of the work is a small
machine-learning model that looks at a signal-strength value the DW1000
already reports and predicts how much a blocked distance is too long. The
system subtracts this amount before computing the position. We trained the
model on 298\,179 real DW1000 measurements from the public UTIL dataset.
On held-out real data it cut the blocked-path part of the distance error by
21.6\%; a simple threshold rule with a fixed metal correction does as well on
single distances (28.3\%), but the learned model gives better positions. In a
test with three anchors and one blocked link, it lowered the position error
(RMSE) by 22.7\% compared with plain least squares and by 1.2~cm compared with
the threshold rule. In a simulated warehouse with metal racks, it lowered the
mean tracking error from 29.1~cm to 12.9~cm. The hardware tests on our own
DW1000 nodes have not been run yet, so we report simulator predictions for
them and mark them clearly.
\end{abstract}

\section{Introduction}
\IEEEPARstart{K}{nowing} where things are inside a building is useful in
many places: warehouses, factories, hospitals and labs. A warehouse manager
may want to know where each forklift is, or get an alert when a worker
enters a danger zone. Outdoors, GPS solves this problem. Indoors, the
satellite signal is too weak after passing through the roof and walls, so
GPS cannot be used~\cite{zafari2019survey}.

Several indoor methods exist, and each has a weak point.
\begin{itemize}
    \item \textbf{Wi-Fi and Bluetooth signal strength.} These use hardware
    that is already everywhere, but signal strength changes a lot with
    reflections and with people walking past. Typical errors are a few
    metres~\cite{zafari2019survey}.
    \item \textbf{Cameras and motion capture.} These can be very accurate,
    but they are costly, need a clear view, and are affected by lighting.
    \item \textbf{Inertial sensors (IMUs).} These need no outside
    equipment, but small errors add up over time, so the position drifts.
\end{itemize}

UWB radio is a strong option for this job. A UWB radio sends very short
pulses spread over more than 500~MHz of bandwidth. Because the pulses are
so short, the receiver can time their arrival very precisely, and two radios
can measure the distance between them to within about
10~cm~\cite{gezici2005localization,jimenez2017comparing}. Low-cost chips
such as the Decawave (now Qorvo) DW1000 make this affordable~\cite{dw1000usermanual}.

The main problem with UWB is \emph{non-line-of-sight} (NLOS) conditions.
When an obstacle sits between the tag and an anchor, the signal either
slows down inside the material or takes a longer path around it. In both
cases the measured distance is \emph{too long}. Normal position solvers
assume errors are random and average out, but this error always points the
same way, so it pulls the position off~\cite{guvenc2009survey}.

A common fix is to detect blocked links and trust them less, or throw them
away~\cite{kolakowski2017first,barral2019nlos}. This has two problems. First,
with only three or four anchors, dropping a link leaves too few distances
to compute a good position. Second, as our results show, a blocked link is
not always a wrong link: foam and cardboard block the path but barely change
the distance.

\subsection{What this paper adds}
\begin{enumerate}
    \item \textbf{A model that predicts the size of the error, not just
    whether a link is blocked.} It uses one value, the power gap $\Delta P$,
    which the DW1000 already gives with every distance. The system subtracts
    the predicted error and keeps the corrected distance.
    \item \textbf{Training and testing on real DW1000 data.} We use the
    public UTIL dataset~\cite{zhao2024util}, which was recorded with the
    same DW1000 chip and has accurate ground truth. We also point out a
    trap in this dataset that can make a model look far better than it is.
    \item \textbf{A complete working system.} ESP32 and DW1000 nodes, a
    Raspberry Pi 4 gateway, a location engine, and a 3D digital twin in the
    browser, all sharing one data format so that the simulator and the real
    hardware can be swapped without changing the rest of the code.
    \item \textbf{A simulator tuned on real data} and a planned hardware
    test, with predictions written down before the measurements are taken.
\end{enumerate}

The rest of the paper is arranged as follows. Section~II covers related
work. Section~III explains the system. Section~IV explains how positions
are computed and how the model works. Section~V describes the experiments,
Section~VI gives the results, Section~VII discusses limits, and
Section~VIII concludes.

\section{Related Work}
\textbf{Indoor positioning in general.} Zafari et al.~\cite{zafari2019survey}
survey the main indoor positioning technologies. Methods based on Wi-Fi or
Bluetooth signal strength are cheap but usually give metre-level errors.

\textbf{UWB positioning.} Gezici et al.~\cite{gezici2005localization}
explain why UWB can measure distance so well. Jim\'enez Ruiz and Seco
Granja~\cite{jimenez2017comparing} compared three commercial UWB systems,
including Decawave, and found good accuracy in clear conditions but much
larger errors when the path was blocked.

\textbf{Handling blocked links.} Guvenc and Chong~\cite{guvenc2009survey}
review methods for detecting and reducing NLOS errors. Marano et
al.~\cite{marano2010nlos} used machine learning on the full channel
impulse response (CIR) both to detect NLOS and to estimate the error.
Reading the full CIR from a low-cost chip is slow, so other work uses only
summary values such as the first-path power. Kolakowski and
Modelski~\cite{kolakowski2017first} and Barral et al.~\cite{barral2019nlos}
use these values to detect blocked links and down-weight them. Stahlke et
al.~\cite{stahlke2020nlos} use neural networks on the CIR. Our work is
closest to the error-estimation idea of~\cite{marano2010nlos}, but uses
only the single power-gap value that the DW1000 already reports.

\textbf{Digital twins.} A digital twin is a live virtual copy of a
physical system~\cite{grieves2017digital,tao2019digital}. Many industrial
twins run in the cloud. Ours runs on a Raspberry Pi on the local network.

\subsection{Radio Nodes}
Each node is an ESP32 board connected over SPI to an Ai-Thinker BU01
module, which contains the DW1000 chip~\cite{bu01spec,esp32datasheet}. We
use three fixed anchors and one moving tag. The firmware is based on the
open-source arduino-dw1000 library~\cite{thotro2015arduino}. All anchors run
the same program; only their address and antenna-delay value differ.

The tag measures its distance to each anchor using double-sided two-way
ranging (DS-TWR)~\cite{neirynck2016alternative}. After each measurement it
reads two power values from the chip and sends one small JSON message over
Wi-Fi to the Raspberry Pi. The anchors only need USB power. In our tests a
phone hotspot dropped about a third of broadcast packets, so the tag finds
the Pi from a beacon the Pi sends every 2~s and then sends its data
directly to the Pi's address.

\subsection{Gateway}
The gateway runs on a Raspberry Pi 4. Messages arrive one anchor at a time,
so the gateway collects them into one reading per tag per cycle. A cycle
is complete when every anchor has reported, or when enough time has passed
and at least three anchors have reported. Three is the minimum for a 2D
position.

Both the real hardware and the simulator produce the same message format,
called \texttt{uwb.reading/1}. It holds the distance and the two power
values for each anchor. Because of this, the rest of the system does not
know or care where the data came from. The gateway also stores tag
positions in a local SQLite database and pushes live positions to browsers
using Socket.IO. The gateway, engine and viewer run as system services that
start at boot and restart if they crash.

\subsection{Digital Twin}
The digital twin is a web page built with React and
Three.js~\cite{grieves2017digital}. It draws the floor, walls, zones,
anchors and tags in 3D. Each anchor--tag link is drawn green when the path
looks clear and red when it looks blocked. The page also shows recent
tracks, an uncertainty ring around each tag, zone alerts, and a ``ghost''
marker showing where the tag is expected to be one second ahead. A built-in
map editor lets the user draw walls and zones and place anchors.

The project also includes a simple Wi-Fi signal-strength tracker for items
that have no UWB tag. It only places items in rough zones, and we do not
report its accuracy here.

\section{How Positions Are Computed}

\subsection{Measuring Distance with DS-TWR}
The two radios have separate clocks that run at slightly different speeds.
DS-TWR cancels most of this clock error by exchanging three messages: the
tag sends a \emph{Poll}, the anchor sends a \emph{Response}, and the tag
sends a \emph{Final}. From the four time intervals (two round trips
$T_{r1}, T_{r2}$ and two reply delays $T_{d1}, T_{d2}$), the time of flight
is~\cite{neirynck2016alternative}:
\begin{equation}
\hat{T} = \frac{T_{r1} T_{r2} - T_{d1} T_{d2}}{T_{r1} + T_{r2} + T_{d1} + T_{d2}}
\end{equation}
The distance is $\hat{d} = c\,\hat{T}$, where $c$ is the speed of light.
Each board also has a fixed internal delay in its antenna circuit, which
adds a constant offset. We remove it with a one-time calibration at a known
distance~\cite{aps014}.

\subsection{Why Blocked Links Give Long Distances}
We can write a measured distance as
\begin{equation}
\hat{d}_i = d_i + b_i + \epsilon_i
\end{equation}
where $d_i$ is the true distance, $\epsilon_i$ is small random noise, and
$b_i \ge 0$ is the extra length caused by an obstacle. In a clear path,
$b_i$ is close to zero. Behind metal it can be tens of centimetres.

The DW1000 reports two power values with each distance: the total received
power $P_{RX}$ and the power of the first path $P_{FP}$~\cite{dw1000usermanual}.
When the path is clear, most of the energy arrives in the first path, so
the gap
\begin{equation}
\Delta P = P_{RX} - P_{FP}
\end{equation}
is small. When an obstacle weakens the first path, the gap grows. This gap
is free: the chip already measures it, and we send it with every distance.

\subsection{The Learned Correction Model}
We train a model $f$ that takes the power gap and predicts the extra length
$\hat{b}_i = f(\Delta P_i)$. We use histogram-based gradient-boosted
regression trees from scikit-learn~\cite{friedman2001greedy,pedregosa2011scikit}
with 200 rounds, a learning rate of 0.1 and at least 200 samples per leaf.
Large leaves stop the model from memorising single recordings.

We predict the \emph{size} of the error instead of a blocked/clear label
because, as Section~VI shows, many blocked links have almost no error. A
blocked/clear label would throw away good distances.

The engine then shortens the distance and gives it a trust weight:
\begin{align}
d_i^* &= \max(0,\ \hat{d}_i - \hat{b}_i) \\
w_i &= \max\!\left(0.1,\ \frac{1}{1 + (\hat{b}_i / 0.10\,\text{m})^2}\right)
\end{align}
The weight halves when the predicted error is 10~cm. The lower limit of 0.1
means no distance is ever thrown away, which matters when there are only
three anchors.

\textbf{Matching the gap scale.} UTIL reports the power gap on its own
scale, where clear links have a median gap of 13.09~dB. A different board
and antenna can have a different typical gap. So for each site we measure
the typical clear-path gap $\Delta P_0$ once, and shift every gap by
$13.09 - \Delta P_0$ before giving it to the model. Without this step the
model performs worse than no model at all (Section~VI).

\textbf{Simple rule for comparison.} As a baseline, and as a fallback if
the model cannot be loaded, the engine can use a simple rule that does not
shorten the distance and only lowers its weight:
\begin{equation}
w_i = \frac{1}{1 + 0.25\,\max(0,\ \Delta P_i - \Delta P_0)}
\end{equation}

\subsection{Computing the Position}
Our anchors sit near the ceiling at about the same height. With all anchors
at one height, the vertical position of the tag cannot be measured
reliably~\cite{torrieri1984statistical}. So we solve for the 2D floor
position and assume a fixed tag height $h_t$. Each distance is first
projected onto the floor using the height difference to its anchor:
\begin{equation}
r_i = \sqrt{(d_i^*)^2 - (h_i - h_t)^2}
\end{equation}
The 2D position $\mathbf{p}$ is then found by weighted least squares:
\begin{equation}
\hat{\mathbf{p}} = \arg\min_{\mathbf{p}} \sum_{i=1}^{N} w_i
\left( \lVert \mathbf{p} - \mathbf{a}_i \rVert - r_i \right)^2
\end{equation}
where $\mathbf{a}_i$ is the floor position of anchor $i$. We solve this
with the Levenberg--Marquardt method~\cite{marquardt1963algorithm} in
SciPy, starting from the previous position.

\subsection{Smoothing with a Kalman Filter}
Single position fixes jump around. A Kalman filter~\cite{kalman1960new}
smooths them by assuming the tag moves at a roughly constant speed between
updates~\cite{li2003survey}. The state is
\begin{equation}
\mathbf{x} = [x,\ z,\ \dot{x},\ \dot{z}]^T
\end{equation}
(position and speed on the floor). We use an acceleration noise of
2.0~m/s$^2$ and a measurement noise of 0.1~m, which matches the 7--12~cm
error of a single fix. (An earlier value of 0.5~m made the filter trust its
constant-speed model too much; Section~VI compares the two.) Throughout, $x$
and $z$ are the floor axes and $y$ is height. The filter also gives a speed
estimate, used for the one-second ``ghost'' prediction, and an uncertainty,
drawn as a ring in the twin.

\subsection{Calibrating the Simulator}
Before the hardware was ready, we built a simulator that produces the same
readings as real nodes~\cite{paszek2021simulator}. A link is blocked if it
crosses a wall in the floor plan. A blocked link gets a positive extra
length that depends on the wall material, and its power gap is widened.
We first guessed these values, then tuned them on real DW1000 data from
UTIL. The tuned clear-path noise is 5.4~cm. For the extra length, each
blocked wall draws one real per-recording value of its material: 18--58~cm
for metal (mean 31.5~cm, as in UTIL), 0--40~cm for wood, and 0--7~cm for
foam, cardboard and plastic. An earlier version drew metal uniformly from
19.8--58.3~cm, which overstated the real mean by about a quarter. Because the
simulator and the model are both tuned on UTIL, simulator tests partly check
the model on data that looks like its own training data.

\section{Experiments}

\subsection{Data}
UTIL~\cite{zhao2024util} is a public UWB dataset from the University of
Toronto, recorded with DWM1000 modules (the same DW1000 chip as ours) and
checked against a Vicon motion-capture system. Part of it has fixed
recordings of a tag and two anchors, both with a clear path and with an
obstacle of a known material in between. From these we take 298\,179 link
samples from 61 recordings, with six recordings for each material.

\textbf{A trap in the data.} In UTIL, every blocked link is exactly
3.94~m long. A model that is given the distance learns ``3.94~m means
blocked'' and scores 97\% accuracy, but it has learned nothing useful.
For this reason we do \emph{not} give the distance to the model, and our
tests check this.

\subsection{Tests}
\textbf{Test A: distance correction.} Five-fold cross-validation on all
UTIL samples. Folds are split by recording, so the model is never tested on
a recording it was trained on. We compare no correction, linear regression,
a \emph{threshold rule} and the gradient-boosted model. The threshold rule
is a two-class scheme like~\cite{kolakowski2017first}: inside each training
fold it picks a gap threshold, and it subtracts the average extra length of
the training links above that threshold from every link above it.

\textbf{Test B: positioning with one blocked link.} Three anchors at
$(0,0)$, $(6,0)$ and $(3,6)$~m. In each trial a tag is placed at random,
and one link is blocked using a real held-out UTIL sample of a random
material. The other two links use real clear-path samples. We compare plain
least squares, the simple rule (with a 3~dB baseline, and with the
baseline matched to UTIL), the threshold rule and the learned model. We run
10 seeds of 2000 trials each; each seed holds out a different set of
recordings (about two of the six metal recordings), so we give 95\%
confidence intervals across the ten splits.

\textbf{Test C: the full engine in a simulated warehouse.} A
$30 \times 30$~m warehouse with five ceiling anchors, two 20~m rows of metal
racks, and wooden outer walls, plus the same floor with no walls. Three
tags move around for 200~s; we run three seeds for each case.

\textbf{Test D: TDoA comparison.} Many low-cost systems use time difference
of arrival (TDoA) instead of two-way ranging. We ran an extended Kalman
filter (EKF) for TDoA on 18 real UTIL drone flights and on simulated TDoA
data for the warehouse.

\textbf{Planned hardware tests.} A $6 \times 6$~m room with three anchors on
tripods at 2.0~m height, the tag at 0.6~m, and a $5 \times 5$ grid of taped
points 1~m apart, measured with a laser meter. The tests are: distance
accuracy before and after antenna-delay calibration, positioning in a clear
room, and positioning with a 2~m metal cabinet in front of one anchor.

\textbf{Measures.} For distances we report the RMS of the remaining
blocked-path error $b_i - \hat{b}_i$. Clear links have $b_i = 0$ by
definition, so this measure leaves out ordinary clear-path noise; it is not
the total distance error. For positions we report RMSE, the median (P50) and the
90th percentile (P90) of the 2D error.

\subsection{Blocked Does Not Mean Wrong}

\subsection{Test A: Distance Correction}
With no correction, the remaining blocked-path error is 9.54~cm RMS. Linear
regression lowers it to 8.48~cm (11.1\% less). The gradient-boosted model
lowers it to 7.48~cm (21.6\% less). Adding the signal-to-noise ratio as a
second input did not help (7.51~cm), so we use the gap alone.

The threshold rule does better here: 6.85~cm (28.3\% less). In every fold it
chose a threshold of about 20~dB, the same step the learned curve finds. So
for single distances, the continuous model adds nothing over a good
threshold. The reason is that the model adds 2--3~cm of over-correction on
clear links and light materials (a few clear links happen to have large
gaps), while the threshold rule leaves them alone. Almost all of the gain of
both methods comes from metal, where the error falls from 34.3~cm to 21.8~cm
(learned) or 18.4~cm (threshold). On wooden shelves it barely changes (20.2
to 19.4~cm at best).

\subsection{Test B: Positioning with One Blocked Link}
Table~\ref{tab:pos} shows the results over 20\,000 position fixes. The
simple rule helps only a little, because lowering the weight of one of
three distances still leaves its error in the answer. The learned model
lowers the RMSE to 9.38~cm, which is 22.7\% below plain least squares and
13.4\% below the matched rule. The P90 falls from 20.38~cm to 11.84~cm
(41.9\% lower).

Here the ranking against the threshold rule reverses. The threshold rule has
a slightly better median and P90, but a higher RMSE (10.61~cm). When metal is
in the way, one fixed correction fits poorly for links far from the average:
the RMSE is 14.4~cm for the learned model, 18.8~cm for the threshold rule and
23.7~cm for plain least squares. Across the ten splits, the learned model
beats plain least squares by 2.71~cm (95\% CI 1.18--4.24), the matched rule
by 1.43~cm (0.25--2.62) and the threshold rule by 1.15~cm (0.26--2.04). With
foam and cardboard the model is about 6~mm worse because of over-correction.

\subsection{Test C: Full Engine in a Simulated Warehouse}
Table~\ref{tab:sim} shows the full engine on simulated data. In the
warehouse, where tags are often behind metal racks, the learned model lowers
the mean error after the Kalman filter from 29.1~cm to 12.9~cm (56\% less)
and the P90 from 53.7~cm to 23.3~cm. The gain is the same 56\% with the
earlier, inflated metal model (36.8 to 16.2~cm), so it does not depend on
it. Without the gap-scale matching step, the same model makes things worse
(mean 41.2~cm), because it treats blocked simulated links as clear.

On the open floor the learned model looks slightly better than the rule (7.6
against 8.8~cm), but this is partly luck. The model subtracts about 2.3~cm
from every clear link, and in this test the anchors keep an uncalibrated
antenna delay of about 10.6~cm, which that subtraction partly cancels. With
the delays calibrated, the learned model is 2~mm \emph{worse} (4.9 against
4.7~cm). So on clear paths the correction costs a few millimetres. This is
also why it is slightly worse in the predicted clear room below.

The Kalman filter setting mattered. With a measurement noise of 0.5~m (about
five times the real fix error), the filter's own position spread settled at
0.33~m, and on the open floor it raised the mean error from 7.8 to 10.0~cm.
With 0.1~m it lowers the open-floor mean from 7.8 to 7.6~cm and the
warehouse mean from 14.2 to 12.9~cm. The gain stays small, because a tag
standing behind a rack has the same error for many updates in a row, and a
filter cannot remove a steady error~\cite{guvenc2009survey}.

One engine update takes 1.40~ms with the learned model and 0.82~ms with the
simple rule, measured on an AMD Ryzen~5 5625U laptop. The update period is
200~ms, so the slower Raspberry Pi~4 should keep up, but we have not yet
timed the engine on the Pi itself.

\subsection{Test D: TDoA Comparison}
On UTIL drone flights in constellations 1 and 2, the TDoA filter reached a
3D RMSE of 0.17--0.20~m in all twelve flights. In constellation 3, five of
six flights reached 0.25--0.33~m, and one flight lost track (5.84~m RMSE)
and did not recover. On the simulated warehouse, TDoA reached a 2D RMSE of
0.51--0.57~m, compared with 0.16~m for our two-way ranging engine. Part of
this gap could come from the noise models, because the TDoA simulator uses
noise fitted to UTIL flights (13.7~cm), about three times what two
two-way-ranging distances would give (7.6~cm). With the TDoA noise set to
7.6~cm, TDoA still reaches only 0.48--0.51~m. So most of the gap is
geometric: ceiling anchors at one height constrain TDoA
poorly~\cite{torrieri1984statistical}, and each TDoA value still combines
two arrival times~\cite{gezici2005localization}. For a small site,
two-way ranging is the better choice. TDoA is still useful for sites with
many tags, because each tag only needs to transmit.

\subsection{Predicted Hardware Results}
\textbf{These are simulator predictions, not measurements.} For the planned
test room, the tuned simulator predicts that before antenna-delay
calibration every distance is about 10.6~cm too long, and after
calibration the error is centred on zero with about 5.4~cm of spread. In a
clear room it predicts an RMSE of 6.1~cm after the Kalman filter. With the
metal cabinet, it predicts 30.2~cm for plain least squares, 24.1~cm for the
simple rule, and 10.8~cm for the learned model after filtering. With only
three anchors, a reading with one bad link gives no position at all; this
is predicted for 3.3\% of readings in the clear room and 17.6\% with the
cabinet. Adding a fourth anchor is predicted to bring the errors down to
4.8~cm (clear) and 6.5~cm (cabinet), so a fourth anchor is the most useful
single upgrade. We will replace these numbers with real measurements once the
hardware tests are done.

\section{Discussion and Limitations}
\textbf{Blocked does not mean wrong.} Three of the six UTIL materials block
the path but leave the distance almost unchanged. A blocked/clear
classifier would lower the weight of these good links, and with only three
anchors every lost distance hurts. Predicting the size of the error lets
the solver keep a corrected distance at nearly full weight. A simple
two-class version (threshold plus a fixed metal correction) already gets
much of this benefit; the continuous model adds about 1.2~cm of position
RMSE on top, almost all of it on metal links far from the average.

\textbf{What the power gap can and cannot see.} The gap reliably detects
metal, which is the most important obstacle in a warehouse. It cannot
detect wood, whose gap is actually lower than a clear path. This is a limit
of the gap value itself, not of the model. Reading parts of the full CIR
would be needed to catch wood~\cite{stahlke2020nlos,marano2010nlos}.

\textbf{Limits of this study.}
\begin{itemize}
    \item The model was trained on UTIL's modules, which use the same chip
    but different antennas and firmware. Its labels also come from TDoA
    data but are used on two-way-ranging distances, which assumes the
    obstacle affects both directions equally. Without the gap-scale
    matching step the model makes results worse, and a single shift cannot
    fix a difference in slope, so the model should be retrained with some
    labelled data from each site.
    \item Tests B and C and the hardware predictions use simulated geometry,
    and the simulator is tuned on the same data as the model. The simulator
    widens the gap by the same amount behind every wall, while UTIL shows
    that wood and light materials do not widen it. So the simulator is
    optimistic for wooden obstacles, including the wooden outer walls of
    the Test C warehouse.
    \item The tag ranges to the anchors one after another, about 80~ms from
    first to last, but the engine treats them as simultaneous. At 1.6~m/s
    the tag moves about 13~cm in that time. The simulator does not model
    this, so a walking test will show it as an extra error unless the fix
    is corrected for the timing.
    \item The 1.40~ms update time was measured on a laptop, not the Pi.
    \item Each UTIL material has only six recordings, and every blocked
    link in UTIL is 3.94~m long, so we could not learn how the error
    changes with distance.
    \item The hardware tests on our own DW1000 nodes have not been run yet.
    \item Positions are 2D only, because our anchors are all at about the
    same height.
\end{itemize}

\section{Conclusion and Future Work}
We built a low-cost UWB tracking system from ESP32 and DW1000 nodes, a
Raspberry Pi 4 gateway and a browser-based 3D digital twin. Its key part is
a small gradient-boosted model, trained on real DW1000 data, that predicts
how much a blocked distance is too long from one value the chip already
reports, and then corrects and re-weights that distance. On held-out real
data, it cut the blocked-path distance error by 21.6\%, where a simple
threshold rule cut 28.3\%. With three anchors and one blocked link, it gave
the lowest position RMSE: 22.7\% below plain least squares and 1.2~cm below
the threshold rule. In a simulated warehouse it more than halved the mean
tracking error. We also found that a blocked link is
not always a wrong link, and that the power gap detects metal but not wood.

Next, we will:
\begin{enumerate}
    \item run the planned tests on our DW1000 hardware and retrain the model
    with labelled data from our own site;
    \item profile the full engine on the Raspberry Pi 4, and correct each
    fix for the time between anchor measurements;
    \item read selected CIR values to detect wooden obstacles;
    \item add anchors at different heights to support 3D positions;
    \item give each material its own power gap in the simulator;
    \item try a motion model that handles sharp turns better than the
    constant-speed Kalman filter~\cite{li2003survey}.
\end{enumerate}
